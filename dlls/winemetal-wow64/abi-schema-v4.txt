Dispatch and copy contract
The exported 138-entry function table and metadata are immutable and identity-bound to this companion Mach-O.
The original normal and legacy source tables may reside in writable storage; the loader validates them, copies all 138 entries from each, revalidates the original contents and identity, then invokes bind synchronously with the stable copies.
Bind independently double-copies and validates the stable source tables, copies them into companion-owned anonymous storage, and makes the complete snapshot read-only before release-publishing it.
Successful repeated bind compares the protected snapshot contents and codec identities; dispatch never dereferences either binding source table after publication.
Snapshot allocation or protection failure publishes nothing and leaves first bind retryable; the loader drains registered calls before companion unload and its destructor unmaps the single published snapshot.
Pinned source slot 083 is null in both tables; snapshots preserve null entries and internal source dispatch reports STATUS_NOT_SUPPORTED for them.
Every wrapper requires an active call context with exact args_size and exact reviewed flags for its slot.
The loader passes a native-owned stable outer snapshot; no implementation may retain that snapshot pointer.
Before any implementation side effect, the wrapper decodes and write-probes the exact canonical guest outer range.
After implementation, the wrapper atomically publishes the complete outer snapshot, including deterministic failure outputs.
Recoverable atomic publication failure writes no bytes; observer failure after stores is fail-stop.
Every nested pointer is decoded with ntdll_wow64_guest32_to_host and accessed only through ntdll current-process copy, probe, or atomic-publication helpers.
Forward entries call only the same-index original legacy-wow64 handler.
Adapted entries call only the same-index original normal handler after bounded snapshots and explicit conversion.
Denied entries return STATUS_NOT_SUPPORTED after the listed deterministic output initialization.
