Dispatch and copy contract
The exported 138-entry function table and metadata are immutable and identity-bound to this companion Mach-O.
The original normal and legacy source tables may reside in writable storage; the loader validates them, copies all 138 entries from each, revalidates the original contents and identity, then invokes bind synchronously with the stable copies.
Bind independently double-copies and validates the stable source tables, retains their single original Mach-O image with RTLD_NOLOAD, copies them into companion-owned anonymous storage, and makes the complete snapshot read-only before release-publishing it.
Successful repeated bind compares the protected snapshot contents and codec identities; dispatch never dereferences either binding source table after publication.
Snapshot allocation, image-retain, or protection failure publishes nothing and leaves first bind retryable; after the last owner, the loader invokes the armed v6 quiesce callback exactly once outside its registry lock while both images remain pinned, then invokes the armed v6 unbind callback exactly once after registered calls drain.
Successful unbind drains AIR, unmaps the single published snapshot, and releases the original image retain last before the loader clears the dispatch slot; failed unbind quarantines the closing slot and backend pins and forbids identity reuse.
Shared-event listener tokens encode a monotonically increasing generation and one of 64 bounded registry slots; they are never native pointers, stale generations fail with STATUS_INVALID_HANDLE, and a closing token accepts no new notification.
Shared-event notification callbacks remain unarmed until notifyListener returns successfully; a callback fired during registration is delivered only after that success, while a faulting registration cancels both the synchronous callback and every later invocation of the copied block.
Listener quiesce first prevents new token creation, retires every live generation, and returns the first guarded stop or cleanup failure so the loader can quarantine the companion; resume only reopens creation after a successful new binding lifecycle.
Pinned source slot 083 is null in both tables; snapshots preserve null entries and internal source dispatch reports STATUS_NOT_SUPPORTED for them.
Every wrapper requires an active call context with exact args_size and exact reviewed flags for its slot.
The loader passes a native-owned stable outer snapshot; no implementation may retain that snapshot pointer.
Before any implementation side effect, the wrapper decodes and write-probes the exact canonical guest outer range.
After implementation, the wrapper atomically publishes the complete outer snapshot, including deterministic failure outputs.
Recoverable atomic publication failure writes no bytes; observer failure after stores is fail-stop.
Every nested pointer is decoded with ntdll_wow64_guest32_to_host and accessed only through ntdll current-process copy, probe, or atomic-publication helpers.
Forward entries call only the same-index original legacy-wow64 handler.
Adapted entries call only the same-index original normal handler after bounded snapshots and explicit conversion, except the documented local slot 18 and slot 114 ownership branches.
Denied entries return STATUS_NOT_SUPPORTED after the listed deterministic output initialization.
